# Troubleshooting

| Symptom | Fix |
| --- | --- |
| New sessions lack `git_bash` / `wsl_bash` | Check the rows are in the profile's `cordis.patch.yml` and that the profile resolves `dsh-win-multi-bash` (`dsh plugin --profile web list`); the bundle layer is assembled at boot, so restart the running `dsh web` |
| Boot fails with `duplicate loader entry id` | The rows are present twice — a hand-written block in the profile patch next to the bundle install; remove one of them |
| Boot fails with `Cannot find package '@deepseek-ai/...'` | The profile runtime lacks the base packages (every standard deployment has them); reinstall with `dsh plugin --profile web add dsh-win-multi-bash` |
| `git_bash` reports bash not found (or spawns the WSL `WindowsApps\bash.exe` alias with `spawn ... ENOENT`) | Git Bash is outside the probe paths, or a stale WSL app-execution alias shadows resolution: delete `%LOCALAPPDATA%\Microsoft\WindowsApps\bash.exe` (Settings → Apps → Advanced app settings → App execution aliases), or set `gitBash.bashPath` manually |
| `wsl_bash` errors | Check `wsl.exe --status` for a default distro; set `wslBash.wslDistro` to name one |
| `wsl_bash` fails with `bwrap was not found` | `sandbox: bwrap` is set but bubblewrap is missing inside the distro: install it per [Sandbox behavior](sandbox.md) (`sudo apt-get install -y bubblewrap`) and restart `dsh web`, or use `sandbox: auto` / `none` |
| `wsl_bash` sandbox reports a runner failure on bwrap | The bwrap workspace root is the Linux side of a Windows drive path (`/mnt/<drive>/...`): a UNC workspace root fails loud, and a distro with a custom automount root (wsl.conf `automount.root`) needs a matching configuration |
| `Plugin dsh-win-multi-bash@… is incompatible with dsh …: requirements {"engines.dsh":"…"}` | The runtime is outside the window `package.json` declares (`engines.dsh`, currently `>=0.1.7-rc.2 <0.3.0-0`). Install a plugin release that covers this dsh, or take the exact-version exemption the message prints (`dsh plugin allow-version`) — running outside the window may crash or lose data |
| Calling `wsl.exe` (or other native exes) with POSIX paths from `git_bash` reports `No such file or directory` | MSYS rewrote `/root` etc. to `<Git root>\root`: prefix with `MSYS_NO_PATHCONV=1` / `MSYS2_ARG_CONV_EXCL="*"`, or use a `//` prefix; use the `wsl_bash` tool for WSL work |
| A wrapped command suddenly fails with `windows-acl-run: --temp is not an existing directory: …` (or `sandbox-unavailable`) and keeps failing on every call | The session's private sandbox temp root is gone — removed out of band (an OS temp cleaner, a manual `rmdir`, another process); who removed it is recorded nowhere, because the host keeps no run log. With `guardSandboxTemp` on (the default) the plugin repairs it at the shared `ctx.sandbox.confine()` seam, so the **next** confined call of any tool (`git_bash`, `msys2_bash`, `run_code`, `pwsh`) recreates the directory and re-applies its write grant, and the timer (`tempWatchMs`) restores it even when nothing runs; retry once. Recreating the directory by hand restores existence only (a confined child's own `%TEMP%` writes stay denied) |
| `wsl_bash` still runs without a sandbox after installing bubblewrap | The bwrap probe verdict is cached for the host process lifetime: restart `dsh web`, or reload the tool row by editing the profile patch |
| Boot warns `win-mb-tool-git … waiting for service: shell` (or dsh's own `tool-pwsh` / `permission-presets` do) | Nothing provides `ctx.shell`. This plugin no longer provides it either: check the base bundle's `pwsh-sandbox` row is not disabled by some other patch |
| `ssh_shell` fails with `no hosts are configured` | The registry is empty. Enable `win-mb-tool-ssh` and add at least one entry to `sshShell.hosts` (`alias`, `host`, `user`, `keyPath` are the minimum) — a valid empty array is a configured-but-useless row, and every call says so |
| `ssh_shell` fails with `sshShell.hosts is invalid (…)` | The message names the field and the alias: a duplicate alias, a missing `host`/`user`/`keyPath`, a port outside 1–65535, or two `default: true` hosts. Fix that entry; the row registers no hosts until it parses |
| `ssh_shell` fails with `the alias is required` | Pass `alias` in the call, or mark exactly one host `default: true` in the registry. Where a command runs is never inferred from the first entry |
| `ssh_shell` fails with `host key not found in known_hosts` | The host key is not recorded. The call is refused by design: connect once with the OpenSSH client or `ssh-keyscan` to add the entry, or set `acceptNewHostKeys: true` on that host to accept the unknown key for one connection (a warning prints the line to add; nothing writes the file, and a changed or `@revoked` key still fails) |
| `ssh_shell` fails with `host key mismatch` | The host presents a different key than `known_hosts` stores; the refusal prints both fingerprints. Verify the host was rebuilt, then remove the stale line (or pin the new key) — this is never bypassed by `acceptNewHostKeys` |
| `ssh_shell` refuses `workdir` | A remote command's directory is a path on the host: an absolute POSIX path such as `/home/me/project`. A local Windows path (drive letter, backslash, UNC) and a relative path are refused by name instead of `cd`-ing somewhere nobody named |
| `ssh_shell` fails naming a `passphraseEnv` variable | The private key is encrypted and that environment variable is unset or wrong. Set it in the dsh process environment (the value is never written to config) — or use an unencrypted key |
| `ssh_shell` refuses a command, naming `requireSandbox` | That row demands a file-sandbox fence, and nothing on this host can fence a remote effect. Turn `requireSandbox` off on that row, or pass `sandbox_permissions: "danger-full-access"` with a justification for that one call |
| `ssh_shell` returns `sandbox.remote: true` and no `denied` | That is the honest shape rather than a bug: the local file sandbox does not govern a command that runs on another host (see [Sandbox behavior](sandbox.md)). A `denied` there would be a verdict nobody observed |
| Stopping an `ssh_shell` call left a remote process running | Timeout/cancel sends `SIGTERM`, then `SIGKILL` after 2 s, and closes the channel; a process that detached itself (`nohup`, `setsid`, a service) survives by design. Make long remote work self-limiting on the remote side (`timeout`, `systemd-run`), or run it in a `terminal` session with `shell: ssh_shell` |
| `ssh_scp` fails with `phase: "sandbox"` and the family sandbox sentence | `localPath` resolved outside the session's workspace root. Move it inside, or run the session under the `danger-full-access` permission — the transfer tool has no per-call `sandbox_permissions` argument; the result then carries `outsideWorkspace: true`. A transfer never silently clamps a path |
| `ssh_scp` fails with `is a local Windows path` or `is relative` (phase `config`) | `remotePath` names a path on the other host: an absolute POSIX path. On a Windows OpenSSH host use the `/C:/Users/...` form; a local `C:\...` path and a relative path are refused before anything is dialled |
| `ssh_scp` fails with `is a directory; pass recursive: true` | The path names a directory. Add `recursive: true` to transfer a tree — empty directories are preserved and missing parents are created on both sides |
| `ssh_scp` fails with `timed out after … ms` | The operation hit its own deadline (`timeoutMs`, default 5 minutes). That covers a stalled dial, a subsystem request the server never answers, and a stalled transfer; raise `timeoutMs` for a large transfer or split it |
| `ssh_scp` answers `ok: false` instead of throwing | By design: every expected failure is a structured value with `error.phase` (`config`, `sandbox`, `connect`, `sftp`), `error.alias` and the ssh2 message. Only a cancelled call surfaces as the platform abort |
| `ssh_scp` succeeds with `outsideWorkspace: true` | `danger-full-access` allowed a `localPath` outside the workspace. The field is the disclosure, not a failure |
| `ssh_scp` reports the same `no hosts are configured` / `sshShell.hosts is invalid` / alias errors as `ssh_shell` | Both tools read the one host registry: fix the entry (or pass the alias / mark exactly one `default`) once for the row |
| `ssh_shell` / `ssh_scp` refuses with `is not authorized for this session` | The host's `approval` is `session` (the default) and this session holds no grant: the answer was rejected or cancelled, the session approval policy is `never`, or no approval service answered. Retry to ask again; for headless use set `approval: trusted` on that host (a deployment setting — the model and call arguments cannot) |
| A new session asks for the same host again | By design: grants are session memory only (a `WeakMap` keyed by the Session object), never on disk, never shared across sessions, and lost on plugin reload |
| Editing a host's port, user or key path asks again | Expected: the grant fingerprint covers alias + host + port + user + keyPath + passphraseEnv, so editing any of them invalidates the old grant |
| `ssh_scp` fails with `phase: "approval"` | The gate refused before any dial; the message is the one `ssh_shell` throws. Fix as above — this is a structured result, not a connection error |
| The dedicated approval card says the answer could not be delivered | The request is still pending: retry the button, or answer it from the platform's standard approval card (the fallback). The plugin never fabricates a grant |
| A `terminal` session says `no ssh client was found` | Only a session uses the OpenSSH client (`ssh_shell` itself does not). Install the Windows OpenSSH client, or pin `sshShell.sshPath` on the **terminal** row — the session reads its own pin, not the host registry |
| `terminal` says a session is "gone — closed by the idle reaper" | The session had no `send` / `read` / `signal` for `terminal.idleMs` (default 10 minutes) and was terminated. Open a new session, or raise `idleMs` on the terminal row |
| `terminal` reports `waitReason: "quiet"` and the command plainly has not finished | That is what `quiet` means: the output went silent, which is NOT "the command finished" (a tty echoes input within milliseconds). `read` again, or raise `waitMs` / `quietMs` on the terminal row |
| `terminal` reports `truncated: true` | The session produced more than `terminal.maxBufferBytes` (default 1 MiB) and its oldest output was dropped. Raise the cap, or read more often |
| `terminal` refuses to open with an `allowUnconfined` message | That row is set to `terminal.allowUnconfined: false`; a PTY session cannot be file-sandboxed, so it refuses rather than run unprotected. Set it back to `true` to accept unconfined sessions |
