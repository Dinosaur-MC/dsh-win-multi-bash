# ssh_scp — implementation plan (Plan 2)

## Goal

Add the `ssh_scp` tool to the SAME ssh row that owns `ssh_shell`, so a
transfer uses the row's `sshShell.hosts` registry, the same known_hosts
verification, the same ssh2 connection pool and (Plan 3) the same authorization
gate. Foreground only; transfers are never registered as jobs.

Spec: `docs/superpowers/specs/2026-11-05-ssh-shell-design.md` §10, §13, §14.

## Non-negotiables

- ONE row, ONE Config partition (`sshShell`), ONE `SshShellExecutor` instance
  per row. The row registers TWO tools (`ssh_shell`, `ssh_scp`) from the same
  executor; the pool is created once, so a command and a transfer reuse the same
  TCP connection.
- No second hosts registry, no second Config key, no new patch row. `package.json`
  exports stay `./tool-ssh-shell` (the module now exports both tools' wiring).
- No jobs: `ssh_scp` is foreground only, with its own deadline.
- Local path: resolved against the session cwd; must stay inside the workspace
  root. `danger-full-access` allows an outside path and the result says so.
  A refused path uses the plugin's standard sandbox sentence. Never silently
  clamp a path.
- Remote path: absolute POSIX path. The description states the Windows OpenSSH
  `/C:/...` form. Upload creates remote parent directories; download creates
  local parent directories; `recursive` walks directories.
- Default timeout 300000 ms per operation; expiry aborts the SFTP stream and
  returns a structured error naming alias + phase `sftp`; never hangs.
- Result: `{ ok, bytes, files?, error? }`; errors name alias + phase and keep
  the ssh2 message. Keys, passphrases and file contents are never logged.
- No version bump, no RELEASE_NOTES edit in this plan.

## Tasks

### Task 1 — the second tool on the ssh row

- Refactor `lib/tool-bash/types/factory.js` so the per-tool registration body is
  callable more than once (`registerShellTool(ctx, declaration, executor)`),
  while `defineShellTool` keeps its current single-tool behavior for the local
  dialects.
- `lib/tool-bash/types/ssh-shell.js` creates ONE `SshShellExecutor` in `apply`
  and registers `ssh_shell` (existing) and `ssh_scp` (new) with the same instance.
  `Config`, `inject` and the row's apply must not be duplicated.
- Add `lib/ssh-shell/scp-tool.js`: the `ssh_scp` descriptor (parameters below),
  output schema, description facts, execute path. It reads the executor's host
  registry/pool; it does not build a second engine.
- Parameters: `action` enum `upload|download`; `alias` (same §8.1 rule as
  `ssh_shell`, reuses the factory's alias parameter); `localPath`; `remotePath`;
  `recursive` boolean default false; `timeoutMs` integer.
- Description: remote effects; local paths are sandboxed; remote path is POSIX
  absolute (Windows OpenSSH `/C:/...`); no stdin/TTY; foreground only.
- Audit: the ssh row registers exactly these two tool names, both share the
  row's Config; `package.json`/patch exports unchanged; the client registry
  still lists the row; no other tool name is added.

### Task 2 — local path + sandbox resolver

- New `lib/ssh-shell/local-path.js`: `resolveLocalPath({ session cwd, requested,
  workspaceRoot, sandboxMode })` -> `{ path, outsideWorkspace, mode }`.
- Resolve relative paths against the session cwd; normalize; refuse a path that
  escapes the workspace root unless the effective mode is `danger-full-access`
  (then allow and set `outsideWorkspace: true`).
- Refusal text uses the plugin's existing standard sandbox sentence (reuse the
  family helper; do not invent a second wording).
- Tests: inside, outside, `..` escape, absolute outside, danger-full-access
  allowance, symlink-free normalization (no fs walk needed; lexical resolve first,
  then the write/read itself is the only fs access).

### Task 3 — ScpRunner over SFTP

- New `lib/ssh-shell/scp.js`: `ScpRunner({ pool, logger })` with
  `upload({ host, localPath, remotePath, recursive, timeoutMs, signal })` and
  `download(...)`, both resolving `{ ok, bytes, files?, error? }`.
- Use the pooled client's `sftp()`; open one SFTP session per operation, close it
  in `finally`; one transfer per operation (no multiplexing needed).
- File: stream with a byte counter; `fastPut`/`fastGet` only when it preserves
  the byte count and error semantics (otherwise plain streams). Directory:
  recursive walk with `readdir`; create remote/local parent dirs with
  `mkdir(..., { recursive: true })`; `files` is the file count.
- Timeout: `setTimeout` + abort the SFTP stream + close the SFTP session; resolve
  a structured error `{ ok:false, error:{ phase:'sftp', alias, message } }`.
  Caller abort signal does the same and reports `aborted`.
- Errors: name alias + phase `sftp`; keep the ssh2 message; never include file
  contents.
- Tests with the in-process `ssh2.Server` SFTP fixture (generated host key):
  upload/download a file, upload/download a directory tree, parent creation,
  byte count, missing local file, remote permission error, timeout abort,
  recursive=false on a directory is a named error.

### Task 4 — wiring, results and audit

- `ssh_scp` execute: resolve alias (same hostFor/default rule, broken registry
  first), resolve local path, open the pooled connection (same hostVerifier),
  run the runner, return `{ ok, bytes, files?, error? }` plus remote sandbox facts
  (the transfer changes the remote side; local effects are the sandboxed path).
- No background, no promotion, no jobs; the call obeys the row's timeout and the
  caller's signal.
- Audit: tool name/shape/params/output schema, one executor/pool shared with
  ssh_shell (two calls, one TCP), local sandbox refusal, danger-full-access
  allowance, SFTP file+dir round trip, timeout, errors naming alias+phase.
- Keep every existing ssh_shell assertion; audit count only grows.

### Task 5 — docs and migration

- README(s), docs/configuration.md, docs/architecture.md, docs/verification.md,
  docs/troubleshooting.md, docs/conversation-rows.md: document `ssh_scp`
  (foreground, local sandbox, remote /C:/, recursive, timeout, result).
- Migration table: no new name change for scp (new tool); mention both tools
  share `sshShell.hosts` and the session authorization gate (Plan 3 lands the
  gate; until then ssh_scp follows the same approval field semantics as
  ssh_shell — recorded, not enforced).
- Keep README under the 10,000-char audit cap; no RELEASE_NOTES version bump.

### Task 6 — channel-refusal retry (spec §5)

- When the SSH server refuses a new channel (MaxSessions, "administratively
  prohibited"/"channel open failure"), retry with bounded backoff until the
  call's deadline (foreground) or a bounded retry budget (background), then
  report the server error verbatim. Never retry auth/host-key/connection
  failures.
- Backoff: 100 ms, 200 ms, 400 ms, capped at 1 s, no unbounded growth; the call's
  deadline, caller signal and lease release still win.
- Applies to exec channels (ssh_shell foreground/background) and the SFTP session
  open (ssh_scp).
- Audit: in-process server refuses the first N channel opens then accepts
  (assert retry count + final success + one TCP + no lease leak); deadline
  exhaustion reports the server error; abort during backoff; non-refusal errors
  are not retried. No docs claim until this lands; Task 5 docs get a one-paragraph
  addendum after.

## Acceptance

- `git status` clean after each task; audit + `npm test` green on a clean tree.
- One executor/pool per row, shared by both tools (test asserts one TCP for a
  command + a transfer).
- `ssh_scp` uploads/downloads a file and a directory tree; a local path outside
  the workspace is refused with the standard sentence; danger-full-access allows
  it and says so; timeout aborts; every failure names alias + phase.
- Existing ssh_shell behaviour unchanged (505/0/3 baseline must not regress).
- No push, no tag, no release; version stays 0.7.7.
